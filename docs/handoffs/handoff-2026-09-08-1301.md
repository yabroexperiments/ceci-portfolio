## 8. Gotchas & Landmines

- **A long turn and a hung session look identical from outside.** I diagnosed the
  local session as wedged and told AC to `Ctrl+C` and `pkill -f playwright`. It
  was not wedged — it was authoring a 447-line page and pushed 32 minutes later.
  That advice would have destroyed real work. Full reasoning in the decisions
  doc; the short version is that `status: WORKING` proves liveness, never
  progress.
- **`interrupt_session` sends `cancel_queued: true`** — it discards whatever the
  user has typed and queued, not just the running turn. Tell them to retype.
- **There is no message path from a cloud container to a bridge session.**
  `ListAgents` says "no other Claude session is running on this machine" because
  the container is not that machine. `interrupt_session` works by session ID;
  nothing else does.
- **`changhsiju.xyz` is blocked by the agent proxy (403 on CONNECT).** A cloud
  session cannot fetch production, so it cannot verify anything visual. Do not
  try to fix this with TLS flags — it is network policy. Confirm with
  `curl -sS "$HTTPS_PROXY/__agentproxy/status"`.
- **`bs4` is not installed in the cloud container**, so `integrate_2026.py` will
  not run there at all. It is a local-only gate.
- **`git checkout <ref> -- .` in an inspection step dirties the working tree.** I
  did this to read files at another ref and had to stash/drop to recover.
  `git show <ref>:<path>` reads a file at a ref without touching the tree — use
  that instead.
- Three of today's bugs were visual and all three passed structural checks
  (`innerText` does not see hidden descendants; DOM assertions do not see
  `opacity: 0`). The local session wrote up that lesson well in its own decisions
  file — worth reading before verifying anything on this site.
