## 8. Gotchas & Landmines
- **Deploys are cache-invisible to AC.** Always ship "hard-refresh `Cmd+Shift+R`"
  with any "it's live" message. This has now cost three round trips.
- **Two files that LOOK empty are not.** `coinful.html` / `legacy-project.html`
  are iframe wrappers; a text extractor shows only nav + footer. I got this wrong
  and wrote the wrong conclusion into the build script before AC caught it.
- **Her export is reformatted** — attribute order is not stable between drops.
  Any new patch must be attribute-order-agnostic or it becomes a silent no-op.
- **The preview server cannot read `~/Documents`** (macOS TCC): it starts and
  404s everything. Serve from the session scratchpad instead.
- **A hidden browser pane** never fires `rAF`, does not animate smooth-scroll,
  and does not repaint screenshots after a programmatic scroll. Measure
  structurally; set `scroll-behavior:auto` before reading scroll positions.
- **`legacy-project.html` restyling only works same-origin.** It is, in
  production and in local preview — but any change to the iframe `src` that
  reintroduces an absolute origin silently disables all of it.

## 12. Context the Summary Would Lose
- **The build script's gates are the deliverable, not a nicety.** Four of the six
  problems fixed this session were found BY a gate, not by reading code — the
  0-byte WebP, the blanked archive pages, a bad `?project=` key, and a file I
  corrupted with a stray `perl -i`. When adding a feature here, add its gate in
  the same commit. Trust the exit code; the CLAUDE.md instruction "don't
  re-verify these by eye" is load-bearing.
- **Paths not taken:** `<picture>` with a PNG fallback instead of swapping `src`
  — rejected because WebP support is universal since Safari 14 and the extra
  markup would churn her files every drop. Removing `body{overflow-x:hidden}` to
  fix the sticky nav — rejected as the riskier half of the pair (it exists to
  suppress horizontal overflow). Deploying `coinful.html` alongside — deferred,
  not refused.
- **`ui-design.html` uses `target="_blank"` on the cards.** I kept it (her
  markup). With the wrapper the visitor still sees the new site, just in a new
  tab. If she wants same-tab, it is a one-line patch.
- **31 unreferenced PNGs + 51 unreferenced files are reported by the build, not
  errors.** That report line is how the "she converted more images" state gets
  noticed; do not silence it.
- **Intuition worth keeping:** every real defect this session was in the *seam*
  between her design and the site's infrastructure — nav CSS interacting with
  inherited body CSS, links bypassing a wrapper, a conversion that half-failed.
  Her actual page design and copy were clean and needed no changes at all. Look
  at seams first next time.
